# Operating Model

The product owner sets direction. Agents own professional interpretation and execution.

## Owner responsibilities

The owner supplies:
- the idea or problem worth solving;
- business and domain constraints known to them;
- preferences that materially affect the product;
- approval or rejection of consequential product choices;
- feedback after seeing proposals and working software.

## Agent responsibilities

Agents are responsible for:
- clarifying the user problem from available evidence;
- discovering missing product requirements;
- identifying expected category capabilities and interaction quality;
- designing journeys, information architecture and interface behavior;
- choosing appropriate technical architecture and implementation patterns;
- defining security, privacy, reliability, data and operational requirements;
- writing specifications before substantial implementation;
- validating the implemented product against those specifications;
- keeping documentation aligned with the actual system.

## Approval boundary

Prepare a concise decision for owner approval when a choice materially changes product scope, target users, pricing, irreversible data behavior, public contracts, legal/compliance posture, core visual direction, or a costly architectural commitment.

Resolve routine, reversible engineering choices directly using project constraints and playbook guidance. Record meaningful assumptions so they can be revisited.
