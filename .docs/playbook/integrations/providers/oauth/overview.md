# OAuth 2.0 Overview

OAuth 2.0 enables users to sign in with existing accounts (Google, GitHub, etc.) without creating a new password. All OAuth providers share the same underlying flow, with provider-specific configuration differences.

## Shared Shape Across Providers

Every OAuth provider requires the same setup steps:

| Step | What you configure |
|---|---|
| **Client ID** | Public identifier for your application, generated by the provider |
| **Client Secret** | Private key used to exchange authorization codes for tokens; server-only |
| **Redirect URI** | The URL in your app that receives the authorization code after the user consents |
| **Scopes** | The specific permissions you're requesting (email, profile, repo access, etc.) |
| **Consent screen** | What the user sees when they authorize your app — configured in the provider's console |

## Authorization Code Flow

```
User clicks "Continue with Google"
        ↓
App redirects to provider with: client_id, redirect_uri, scopes, state, code_challenge (PKCE)
        ↓
User authenticates at provider and consents
        ↓
Provider redirects back to redirect_uri with: code, state
        ↓
App verifies state matches session value (CSRF protection)
App exchanges code + code_verifier for access_token + id_token
        ↓
App extracts user profile from id_token or profile API
App finds or creates user account
App creates a session
```

## State Parameter — CSRF Protection

The `state` parameter is a random, unpredictable value generated before the OAuth redirect. After the provider redirects back, verify that the returned `state` matches the value stored in the user's session. This prevents CSRF attacks on the OAuth callback.

```typescript
import { randomBytes } from 'crypto';

// Before redirect: generate and store state
const state = randomBytes(32).toString('hex');
req.session.oauthState = state;

const authUrl = new URL('https://accounts.google.com/o/oauth2/v2/auth');
authUrl.searchParams.set('client_id', process.env.GOOGLE_CLIENT_ID!);
authUrl.searchParams.set('redirect_uri', `${process.env.APP_URL}/auth/google/callback`);
authUrl.searchParams.set('scope', 'openid email profile');
authUrl.searchParams.set('response_type', 'code');
authUrl.searchParams.set('state', state);

res.redirect(authUrl.toString());
```

```typescript
// On callback: verify state matches
app.get('/auth/google/callback', async (req, res) => {
  const { code, state } = req.query;

  if (state !== req.session.oauthState) {
    return res.status(400).send('Invalid state — possible CSRF attack');
  }

  // Exchange code for tokens...
});
```

## PKCE for Public Clients

For mobile apps and SPAs where the client secret cannot be securely stored, use PKCE (Proof Key for Code Exchange):

```typescript
import { randomBytes, createHash } from 'crypto';

// Generate code verifier and challenge
const codeVerifier = randomBytes(32).toString('base64url');
const codeChallenge = createHash('sha256').update(codeVerifier).digest('base64url');

// Send code_challenge in the authorization request
authUrl.searchParams.set('code_challenge', codeChallenge);
authUrl.searchParams.set('code_challenge_method', 'S256');

// Store codeVerifier in session to use in the token exchange
req.session.oauthCodeVerifier = codeVerifier;
```

## Account Linking

**Link OAuth accounts by provider user ID, not email.** Email addresses are not stable identifiers — users change their email, or two different people on different providers may share an email format. Two accounts matching by email is a coincidence; two accounts matching by provider user ID is a reliable identifier.

```typescript
// On callback: link by provider + provider user ID
const account = await db.oauthAccount.findUnique({
  where: { provider_providerUserId: { provider: 'google', providerUserId: googleUserId } },
});

if (account) {
  // Existing OAuth account — sign in
} else {
  // New OAuth login — create account or link to existing if signed in
}
```
