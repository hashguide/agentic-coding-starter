# Settings and Administration Architecture

Separate personal preferences, account/security, workspace/organization configuration, billing, integrations and administrative controls by ownership and impact.

A setting should live where users understand what it affects. Use object-level settings for configuration scoped to that object; use global settings only for genuinely global behavior.

Consider:
- personal vs organization ownership;
- role/permission visibility;
- safe defaults and previews;
- autosave vs explicit save;
- destructive settings and confirmation;
- audit requirements;
- mobile layout for dense settings.

Avoid turning Settings into a catch-all for primary workflows that deserve normal product surfaces.
