# Mental Models and Terminology

Structure the product around concepts users already understand or can learn quickly.

## Derive the model
1. List the user's recurring goals in their own language.
2. List the objects they create, inspect, change, share, or monitor.
3. Identify parent/child and cross-object relationships.
4. Identify actions that apply globally versus within one object.
5. Name areas by the user's concept rather than the internal service or database table.

## Evaluate terminology
A label should predict what the user will find after selecting it. Prefer stable nouns for work areas and specific verbs for actions. Introduce domain terms when they reduce ambiguity and can be explained at the point of use.

## Review questions
- Could a first-time user predict where a common task lives?
- Are two labels competing for the same concept?
- Does one label contain several unrelated concepts?
- Are implementation terms visible where user language would be clearer?
- Does the object hierarchy match how users think about ownership and containment?
