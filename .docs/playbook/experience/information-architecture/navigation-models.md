# Navigation Models

## Sidebar
Use for products with several persistent work areas, frequent switching, or deep application usage. It supports scanning and expansion well on desktop. Define a deliberate mobile replacement rather than shrinking it.

## Top navigation
Use when there are few primary destinations, the product is content-heavy, or horizontal space is more valuable than persistent navigation.

## Bottom/mobile navigation
Use for a small set of high-frequency mobile destinations. Keep the number of items low enough to remain recognizable.

## Tabs
Use for peer views of the same object or closely related state. Tabs should preserve the surrounding context. Promote a tab to a route/work area when it becomes a distinct task with its own hierarchy.

## Breadcrumbs
Use when hierarchy is deep or users commonly arrive through direct links. Breadcrumbs clarify ancestry; they are not a substitute for global navigation.

## Contextual navigation
Use actions, secondary nav, or object menus for operations that make sense only inside the current object.

Evaluate navigation by task frequency, breadth, hierarchy depth, user roles, screen size, and the cost of losing context.
