# Information Architecture

Information architecture defines how users understand where they are, where things live, how concepts relate, and how they move through the product. Establish it from user tasks and mental models before polishing individual screens.

## Inputs
- primary user jobs and recurring tasks;
- core product objects and their relationships;
- frequency and importance of actions;
- user roles and permission differences;
- breadth and depth of the product;
- mobile and small-screen constraints.

## Outputs
Record in `project/information-architecture.md`:
- top-level work areas;
- object hierarchy and naming;
- global and contextual navigation;
- route hierarchy;
- search/discovery model;
- where creation, editing and management actions live;
- mobile transformations;
- rationale for non-obvious placement.

Use the related IA documents to choose between task-oriented and object-oriented structures, navigation patterns, and detail surfaces.
